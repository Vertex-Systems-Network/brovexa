# Brovexa — Launch Scope & Implementation Waves

Status: **Planning Only — sequencing, not development authorization**

The complete Brovexa vision remains in scope. Waves define build order so a usable system appears early without throwaway architecture.

## Wave A — Core Usable Intelligence Platform
Goal: an operator can research businesses, inspect evidence/signals/opportunities, qualify Leads and safely resume background work.

Required:
- Web operator + canonical API
- auth/register/recovery/workspace/RBAC/audit foundation
- global geography + industry/service taxonomies
- Research Job Builder + preflight + budgets
- initial approved source adapters + SourcePolicy controls
- Business/Location/Domain/ContactChannel/Source/Evidence canonical entities
- entity resolution/dedup
- website/digital presence verification
- Agent Registry/orchestrator/context/durable memory/checkpoints
- selected high-value signals + custom-definition compiler contract
- Evidence Verifier + opportunity/service reasoning + explainable scoring
- Business 360/Evidence/Signals/Opportunities
- Lead OS: inbox/qualification/score/history/owner/tasks/nurture/re-research
- AI Lead Copilot + human-reviewed outreach drafts
- background job monitor/pause/resume/cancel
- suppression/contact eligibility
- usage/cost/Research Credit accounting foundation
- observability/security/tests/evals/admin

## Wave B — Client & Commercial Beta
- public product/marketing website
- pricing/packages/entitlements/checkout/billing
- Windows-first Desktop client
- Chrome/Chromium extension
- Firefox extension from shared codebase
- cross-client auth/deep links/notifications/sync
- CSV/XLSX import/export
- initial CRM connector(s)
- scheduled/continuous research UX
- broader source/signal coverage
- guided onboarding

## Wave C — Scale, Automation & Ecosystem
- wider licensed/provider connector catalog
- additional CRM/bidirectional sync
- public API/webhook ecosystem
- advanced territory/buying-committee workflows
- wider jurisdiction/channel outreach profiles
- controlled outbound automation only when explicitly approved
- advanced first-party intent
- richer market/competitor intelligence
- daily GitHub product-research scout after approval
- enterprise SSO/governance/data controls
- analytics/attribution/cost optimization
- search/orchestration/infra scale upgrades only after measured thresholds

## Not removed
Desktop, Chrome, Firefox, public website, payments, global geography acquisition, Agent OS/memory, Lead OS, 24-hour scout, CRM, custom signals, packages and full connector-extension architecture remain planned. Wave assignment is not cancellation.

## No-shortcut rule
Wave A contracts must already support later clients, commercial state, connectors and policy profiles. A fast first release may omit adapters/features, but not create incompatible schemas or temporary security/compliance bypasses.

## Wave A usability gate
A user must be able to:
1. register/login/create a workspace;
2. configure services and target market;
3. build a geography/niche/signal/budget ResearchJob;
4. run it in the background;
5. inspect canonical businesses/evidence;
6. view digital intelligence/signals;
7. understand explainable service opportunities;
8. create/qualify/route Leads;
9. receive AI next-best-action/outreach draft;
10. pause/resume/re-research without losing state;
11. see cost/policy/confidence/job status.

If this end-to-end path is not real, Wave A is not considered usable.
